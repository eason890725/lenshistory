此 Skill 用於管理 LensHistory 的器材資料庫 (products.json)
核心執行規則
【版本備份】：修改前先確認 git 工作區乾淨；出錯時用 git restore frontend/src/data/products.json 還原，不再另存 .bak。

【絕對增量】：所有新產品只能追加 (Append) 到陣列末尾，嚴禁刪除或修改既有資料。

【資料驗證】：修改後必須在 frontend/ 執行 npm run validate（npm run build 前也會自動跑）。有 error 不得 commit；若數量意外減少，立即還原並回報。欄位名稱以 frontend/src/lib/gear.ts 的 Gear 型別為準，不得自創別名欄位。

【嚴禁偽造】：僅允許真實產品。資料缺失就不要寫該欄位（網頁會自動顯示「--」），不得寫入「--」「TBD」等佔位字串，也不得把同一段文字套用到多個產品充當規格。

【自動存檔】：通過防呆檢查後，自動執行 Git Commit 並註明更新內容與數量。

【視覺驗證】：任務結束前必須啟動 http://localhost:3000，確認列表渲染正常且無 undefined 並附上截圖。

【價格校驗】：Launch Price 必須 > 0，格式統一為台幣 (NTD)，需與 2024-2026 最新市場 MSRP 核實。查不到就不要填，不得用 0 或固定數字佔位。

【狀態持久化】：篩選組件必須實作 URL 參數同步，確保導覽返回時狀態不遺失。

【原生鏡頭深度提取】：針對頂級系列 (L, S-Line, WR)，必須抓取光學結構、特殊鏡片、鍍膜技術及馬達類型。

【大一統格式鎖定】：強制顯示影像核心、光學性能、功能特性、物理與市場四大區塊。

【資料完整性】：旗艦機型優先查齊感光元件與對焦辨識目標等核心數據；查不到寧可留空，不得用其他機型的值代填。

【單一品牌精確抓取】：地毯式補完規格並執行去重邏輯。

【正名與別名】：modelName 遵循「品牌 + 官方全名」；aliases 存入簡稱，確保搜尋命中。

批次自動化與資源補丁 (New)
【資源釋放與隔離】：

Headless 優先：所有瀏覽器任務必須預設以 headless=True 執行。

即用即關：進入新網址前必須關閉前一個標籤頁 (Tab)。任務結束必須關閉整個瀏覽器實體。

精確終止：執行時必須記錄 PID。嚴禁使用全域殺除指令，僅能針對該任務 PID 執行關閉，不得干擾使用者視窗。

【全譜系採集規範】：執行補完時必須強制執行「分層掃描」。必須涵蓋 Entry (入門機/非 L 鏡)、Mid (中階)、Pro (旗艦) 三大層級。優先檢索入門產品以抵消搜尋權重偏誤。

【影像自動優化】：新抓取的圖片必須執行 Python Pillow 處理，將背景轉換為 純黑色 (RGB 0, 0, 0)，命名遵循小寫連字號 ID。轉黑後執行 python frontend/scripts/clean_image_lines.py <圖檔> 清掉殘留橫線，不要再另寫一次性修圖腳本。只能用產品本身的照片，不得用網頁或購物頁截圖。

【批次檢查點】：大量處理時，以 5-10 個產品為一組。每組完成後強制執行 Rule 3 (防呆) 與 Rule 5 (Commit)，確保進度持久化。
